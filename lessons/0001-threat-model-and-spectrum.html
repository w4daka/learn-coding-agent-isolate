0001 脅威モデルと隔離の物差し

ゴールは一つだ。怖さを4語で言えること。怖さが言えれば、隔離手段は 早見表 から選べる。

知識: 怖さは4種類だけ

脅威例閉じ方
破壊rm -rf ~、DB 削除書ける場所を workspace のみに絞る
窃取~/.ssh/id_ed25519 の読み取り見せる物を明示。見せない物は存在自体消す
送信秘密の外部 POST、C2 通信network を切る・ egress を絞る
汚染悪意ある依存の混入、履歴改竄使い捨て環境＋改変の監査

お前の mission（MISSION.md）の「rm -rf と秘密鍵」は破壊＋窃取だ。まずこの2つを閉じる。

技能: 権限不足を目で見る（5分実験）

隔離の成否は exit code と errno で観測する。今回は非特権 bwrap で EROFS と ENOENT を出す。偽の秘密でやれ。実鍵に触れるな。

mkdir -p /tmp/pi-isolate-lab/work
echo "fake-secret-do-not-use" > /tmp/pi-isolate-lab/fake_secret
chmod 600 /tmp/pi-isolate-lab/fake_secret

# 実験A: 読取専用に触ると EROFS で死ぬ（exit=1）
bwrap --ro-bind /usr /usr --symlink usr/bin /bin \
  --symlink usr/lib /lib --symlink usr/lib64 /lib64 \
  --ro-bind /etc /etc --proc /proc --dev /dev \
  --bind /tmp/pi-isolate-lab/work /work \
  --unshare-pid --die-with-parent -- \
  touch /usr/should-fail; echo "exit=$?"
# 期待: touch: cannot touch '/usr/should-fail': Read-only file system / exit=1

# 実験B: 見せていない秘密は存在しない（exit=1）
bwrap --ro-bind /usr /usr --symlink usr/bin /bin \
  --symlink usr/lib /lib --symlink usr/lib64 /lib64 \
  --ro-bind /etc /etc --proc /proc --dev /dev \
  --bind /tmp/pi-isolate-lab/work /work \
  --unshare-pid --die-with-parent -- \
  cat /tmp/pi-isolate-lab/fake_secret; echo "exit=$?"
# 期待: No such file or directory / exit=1

# 実験C: 許可した場所は書ける（exit=0）
bwrap --ro-bind /usr /usr --symlink usr/bin /bin \
  --symlink usr/lib /lib --symlink usr/lib64 /lib64 \
  --ro-bind /etc /etc --proc /proc --dev /dev \
  --bind /tmp/pi-isolate-lab/work /work \
  --unshare-pid --die-with-parent -- \
  touch /work/ok && ls -l /tmp/pi-isolate-lab/work; echo "exit=$?"
判定基準: A=EROFS・B=ENOENT・C=成功。この3点セットが「閉じた上で仕事ができる」の最小形だ。pi を閉じ込める全手法はこの再現だ。早見表 を見て、bwrap の行が何を閉じたか言え。
